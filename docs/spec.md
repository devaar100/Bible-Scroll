# PROJECT CONTEXT: Free Android Bible-scrolling app (inspired by "Scroll The Bible" on iOS)

## 1. Goal
Build a native Android app that turns the doomscrolling habit into Bible reading: one verse per full screen, swipe up for the next. Inspired by the iOS app "Scroll The Bible", but:
- 100% FREE: no paywalls, trials, upsells, usage caps, "premium" features, ads or tracking.
- Original name, logo, copy, colours and illustrations (nothing copied from the reference app).
- Android-only for now.
- I'm vibe coding with Claude Code (Android Studio plugin). I know basic Java Android, SwiftUI and React Native.

## 2. Reference app: Scroll The Bible (iOS)
- Developer: Gabriel Jacobson / JCBSN LLC. Launched Dec 2025. iPhone only, no Android version.
- 4.8 stars, ~21K ratings, #1–2 in Books (US). Third-party revenue estimates range from ~$750K to ~$2M/month.
- Monetisation: freemium subscription (prices A/B tested: e.g. $39.99/yr or $29.99/yr, $4.99–$9.99/mo, 7-day trial).
- Free tier: verse feed, translations, notes, likes, compare, widget, snapshot, plans, Discover deep studies.
- Paid: on-demand AI verse studies (OpenAI), plus paywalls on first devotional / first plan session (appear soft or frequency-capped), and Community voting.
- Translations: KJV bundled; others (NLT, AMP, NASB, NKJV, NIV, CSB, etc.) via API.Bible/YouVersion. English + Spanish UI.

## 3. User feedback on the reference app (from reviews)
Problems: paywall is the #1 complaint (paying for Scripture, trapped on trial screen, confusion about what's free); cancellation/refund/support failures; some users dislike AI in Bible study; AI studies have no citations; want reading position saved per chapter/book; not enough for experienced readers; App Store privacy label declares tracking for third-party advertising.
Requests: community features (friends, shared verses, prayer), colour customisation beyond light/dark.
What users love: bite-size verses help people who feel overwhelmed (incl. dyslexia/ADHD), chapter tracking, original Greek/Hebrew study, a real doomscroll replacement.

- Verse scrubber (B1 chapter, B2 liked list, H11 day) **[done]**: a segmented position track on the start edge (`ui/components/scrubber/`).
  - Track: one rounded capsule per item, equal heights, 2 dp gaps, one Canvas, from 12 dp under the top bar to 12 dp above the bottom bar (B1: inside the Scaffold, so 76 dp from the top, 12 dp above the navigation bar; H11: 12 dp under the close button). Heights are calculated (`ScrubberLayout`), never hard-coded. If capsules would be under 6 dp, the gap drops to 1 dp, then items are grouped into buckets so every capsule is at least 6 dp (Psalm 119: about 75 capsules); the active bucket lights up and the label still shows the real verse.
  - Geometry: track centre 8 dp from the start edge; inactive capsules 3 dp wide, the active one 5 dp, widening about the same centre; fully rounded ends.
  - Colours (reading-theme tokens, per background): active = onBackground; passed (above) = onBackground at `scrubberPassedAlpha` (>= 3:1); upcoming (below) = onBackground at `scrubberUpcomingAlpha` (about 1.15:1, just visible). Alphas live in ReadingColors (Paper 0.50/0.07, Sepia 0.55/0.08, Charcoal 0.42/0.06, True Black 0.44/0.09). No accent colour.
  - Labels: Inter 10 sp, medium, tabular figures, start edge 15 dp, centred on their capsule, font scaling capped at 1.2x. Three only: first and last (dim, same strength as passed) and the current one (semi-bold, full strength). B1 shows the verse number (a skipped verse such as WEB Acts 8:37 keeps the real numbers), B2 and H11 the item index. An end label fades out while the current one sits on it.
  - Motion: everything follows the pager's continuous position (currentPage + currentPageOffsetFraction), read only in the draw phase. Capsule i has weight w = max(0, 1 - |position - i|): width = lerp(3, 5 dp, w), colour = lerp(base, active, w), base = passed above the position, upcoming below. Mid-swipe the old capsule fades to passed while the next widens and brightens with the finger; the current labels cross-fade (both visible mid-swipe). No bounce, no recomposition during swipes or scrubs.
  - Interaction: touch strip 0 to 48 dp from the start edge (the track at 8 dp sits inside it; a 48 dp strip centred on the track would hang off-screen). Holding the active capsule (grab zone at least 48 dp tall) and dragging scrubs with scrollToPage, one haptic tick per item, and enlarges the current number 1.35x; the reading position is saved on release. A tap elsewhere on the track jumps there. A drag that starts off the active capsule does nothing. Verse text starts past the strip, so drags on text always page. The system back gesture is excluded only in a 160 dp band that follows the active capsule (limit 200 dp); elsewhere on the edge back still works. Checked on an SM-M146B with gesture and three-button navigation (2026-11-19).
  - Visibility: S2 "Verse scrubber": Always (default) / Only while scrolling (shows on scroll or touch, hides 1.5 s after) / Off. Hidden when there is one item.
  - Layout: verse text start padding 52 dp while the scrubber can show (28 dp when Off), enough for "176" at the 1.2x cap while held; ScrubberScreenshotTest checks the scrubber's ink never reaches the text at the largest font and in Spanish.
  - TalkBack: one slider node ("Position in chapter", "Verse 12 of 31", progress range with one step per item, setProgress); the drawing has no nodes.
  - Tests: ScrubberMathTest (buckets, heights, weights, hit testing), ScrubberDragTest (grab, tap, ignored drags, ticks), ScrubberVisibilityTest, ContrastTest (three states and both labels on every background), VerseScrubberTest and ScrubberScreenshotTest (androidTest: 4 backgrounds x first, middle, last, mid-transition, dragging, 31 and 176 verses, largest font, Spanish), ScrubBenchmarks (macrobenchmark: scrubbing Psalm 119).
